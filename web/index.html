    How it works

    1. See

      A small CNN encoder turns the picture (48×40 pixels, or 80×80 in the fog world) into a 64-number latent state.

    2. Imagine

      A predictor guesses the next latent for each of the 4 moves, without touching the real world. Doing this from every cell gives an imagined map of where every move leads.

    3. Plan

      It tries all 64 three-move sequences in imagination and scores each by how close it gets to the goal on that imagined map. Each imagined move snaps to the nearest cell picture it knows, so its imagination can't drift; moves it isn't sure about count as walls.

    4. Act

      It makes the first move, looks again, and plans again.

    Success rate, with the share of runs on a shortest path below. 6 × 5: 24,146 / 19,680 / 8,048 episodes (every free start, two seeds), 30 moves, third visit to a cell is a loop failure. Fog: 4,000 / 2,000 runs (10 starts per map, two seeds), 300 moves. Settings were fixed on validation maps, then each test set was run once.

    Why JEPA. The encoder is trained together with the predictor, against a slowly updated copy of itself, so the latent space makes moves predictable rather than just redrawing the picture. On 1,200 maps it never saw (normal maps, dense walls and winding mazes), it reaches the goal by a shortest path 100% of the time. A model with the same networks trained to redraw the next picture instead solves 79% of the mazes.

    Trained on 70 maps with 3–7 walls (fog world: 10–25); the goal is always top-right. The models run entirely in your browser (about 3 MB of weights, no server). Built from the project's PyTorch checkpoints and checked against them number for number.
